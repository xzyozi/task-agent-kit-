# Template Trial Clone

## 概要

テンプレートリポジトリを、一時ディレクトリへ clone して試用コピーを用意する。
`scripts/setup_trial.py` が clone、コミットの固定、削除を行う。このSkillは、スクリプトの実行前後の確認と案内を担当する。

試用コピーの中で何を確認するか、どんな agent を作るかは、このSkillの対象外である。

## ワークフロー

### ステップ1: 元のリポジトリの確認

1. 現在のディレクトリが、試したいテンプレートのリポジトリであることを確認する（`git rev-parse --show-toplevel`）。
2. 異なる場合は、元にするリポジトリのパスをユーザーに確認する。推測しない。

### ステップ2: 実行前の確認

1. 試用コピーが既に存在するか確認する（既定の場所: 一時ディレクトリの `tak-trial`）。
2. 既に存在する場合は、作り直してよいかユーザーに確認する。承認を得るまで、削除しない。
3. 元のリポジトリに未コミットの変更がある場合は、試用コピーに含まれないことを伝える。

### ステップ3: スクリプトの実行

作成する場合:

```powershell
python scripts/setup_trial.py
```

作り直す場合（ユーザーの承認後）:

```powershell
python scripts/setup_trial.py --force
```

削除する場合（ユーザーの承認後）:

```powershell
python scripts/setup_trial.py --remove
```

必要に応じて、`--source <path>`、`--dest <path>`、`--ref <commit-ish>` を指定する。
`--dest` は、一時ディレクトリ配下で、名前が `tak-trial` で始まるものに限る。

### ステップ4: 結果の報告

出力された作成先、元、コミット、作業ツリーの状態を報告する。
作業ツリーが「クリーン」でない場合は、想定外として報告する。

### ステップ5: 次の操作の案内

作成した場合は、次を案内する。

- 試したいツールで、作成先のフォルダを開く。
- 試したい内容は、ユーザーが決める。このSkillでは指定しない。

## ルール

1. 作成・削除する場所は、一時ディレクトリ配下の `tak-trial*` に限る。スクリプトが拒否した場合は、別の場所を探さずに報告する。
2. 元のリポジトリは変更しない。読み取りのみとする。
3. 既存の試用コピーの削除は、ユーザーの明示的な承認を得てから行う。
4. 外部ネットワークには接続しない。clone は、ローカルのリポジトリから行う。
5. 試用コピーの中身を、依頼なしに編集しない。
6. `git push` はしない。
7. スクリプトが失敗した場合は、エラーを報告し、原因が分かるまで再実行しない。

## 出力フォーマット

```text
状態: 作成済み / 作り直し済み / 削除済み / 停止
作成先: <パス>
元: <パス>
コミット: <短縮ハッシュ> <件名>
作業ツリー: クリーン / 変更あり
注意: <未コミットの変更の警告など。なければ「なし」>
```

## 例

入力例:

```text
試用コピーを作って
```

期待される動き:

1. 現在のリポジトリを確認する。
2. 既存の試用コピーがなければ、`python scripts/setup_trial.py` を実行する。
3. 上の出力フォーマットで結果を報告し、作成先のフォルダを開くよう案内する。

エッジケース:

- 試用コピーが既に存在する → 作り直してよいか確認する。承認があれば `--force` を付ける。
- 元のリポジトリに未コミットの変更がある → 試用コピーには含まれないと伝える。
- `--dest` に一時ディレクトリの外を指定された → スクリプトが拒否する。そのまま報告する。

## ガイドライン

- このSkillは、テンプレートリポジトリの `maintenance/skills/` に同梱されている。正本はこの場所である。
- スクリプトは Python 3.9 以降の標準ライブラリと `git` だけを使う。追加のインストールは不要である。
- 試用コピーは、コミット済みの内容だけを含む。試したい変更は、先にコミットしておく。
- 削除は `--remove` で行える。試用コピーに、保存すべき成果物がないか、削除前にユーザーに確認する。
