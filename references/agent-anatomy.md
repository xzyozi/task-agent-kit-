# agent 定義の構造

特定タスク向けの agent 定義は、次の構造で書く。雛形は `templates/agent.md`。
ここに書かれた構造は、複数の既存 agent（対話型と自律実行型）に共通する要素だけを抜き出したものである。

## frontmatter

| 項目               | 書き方                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| `name`             | 小文字・ハイフン区切り。役割が分かる名前にする                                                 |
| `description`      | 「何をする agent か」と「いつ使うか」を1〜2文で書く。対象と制約を含める                        |
| `tools`            | 使うツールだけを文字列の配列で列挙する。不要なツールを含めない                                 |
| `allowedTools`     | 承認なしで使ってよいツールだけを列挙する。迷う場合は空にする                                   |
| `includeMcpJson`   | 外部ツールが不要なら `false`                                                                   |
| `includePowers`    | 不要なら `false`                                                                               |
| `permissions`      | 能力ごとに `effect`（`ask` または `deny`）を指定する。書き込みが不要なら `deny` にする          |

権限は最小にする。読み取りだけで足りるタスクには、書き込みと実行の権限を与えない。

## 本文の構成

次の見出しをこの順で書く。不要な見出しは省略してよいが、順序は変えない。

1. **役割（冒頭の1〜2文）**: 何を専門とするか、対象は何か、目的は何かを書く。
2. **基本方針**: 作業の進め方を書く。対象を暗黙に推測しない、いきなり変更しない、など。
3. **実行手順**: 番号付きの手順で書く。各手順は、条件と行動が分かる形にする。
4. **実行境界**: やってよいこと、やってはいけないこと、承認が必要なことを分けて書く。
5. **常時制約**: 手順に関係なく常に守ることを書く。認証情報の扱い、停止条件を含める。
6. **報告形式**: 各段階で報告する項目を、項目名つきで列挙する。

## 書き方の規則

- 指示は命令形で終える（「〜する」「〜しない」）。
- 「適切に」「必要に応じて」を使わない。判断基準は条件と行動で書く。
- 同じ内容を複数の見出しに書かない。共通の安全規約は `references/safety-baseline.md` を参照し、複製しない。
- 実在しないコマンド、ファイル、ツール名を書かない。書く前に実在を確認する。
- 停止条件を明記する。「何が起きたら止まるか」が書かれていない agent を作らない。
- 完了条件を明記する。agent が自分で達成を確認できる形にする。

## 型の選択

- **対話型**: 質問と計画提示が中心。書き込み権限は `deny`、実行は `ask` にし、承認後にだけ既存の手順に委譲する。
- **自律実行型**: 失敗の検出から修正、検証までを自分で進める。対象と禁止事項を厳密に絞り、停止条件を多めに書く。

選択に迷う場合は、対話型にする。
